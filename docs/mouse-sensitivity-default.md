# 云游戏默认鼠标灵敏度：数据推导

结论先写：**`mouseSensitivity = 0.5`（游戏内 100%），前端 gain = 1.0（100%）。**
不是拍脑袋，是三个独立数据源加权后的交点，同时也是 Minecraft 的原生默认值。

## 1. 为什么需要推导

串流链路里"灵敏度"实际是三个乘数的积：

```
物理移动 → (客户端 DPI 决定 counts) → (浏览器 gain) → (游戏内 mouseSensitivity) → 视角角度
```

我们的服务端和浏览器都把这个值**原样传递**（gain=1，服务端不缩放），所以最终手感
= `客户端 DPI × 游戏灵敏度`。云游戏无法读取客户端的 DPI，因此"默认值"只能选一个
能让最多玩家落在舒适区的点。

## 2. 换算公式

Minecraft 1.12.2 `EntityPlayerSP.onUpdate`：

```java
float f  = mouseSensitivity * 0.6F + 0.2F;
float f1 = f * f * f * 8.0F;
this.turn(deltaX * f1 * 0.15F, deltaY * f1 * 0.15F);
```

即：

```
每 count 的角度(°) = 1.2 × (0.6 × s + 0.2)³
转一圈所需 count  = 360 / 每count角度
每圈距离(cm)     = count数 / DPI × 2.54
```

## 5. 目标：每圈 8 cm

把上面的样本换算成 cm/360（`s` 为 options.txt 值 = slider% / 100）：

| 配置 | s | 每圈距离 |
| --- | --- | --- |
| 70% @ 800 DPI | 0.70 | 4.0 cm |
| 65% @ 800 DPI（中位） | 0.65 | 4.6 cm |
| 60% @ 600 DPI | 0.60 | 7.2 cm |
| 55% @ 1200 DPI | 0.55 | 4.3 cm |
| 45% @ 800 DPI | 0.45 | 9.2 cm |
| 24% @ 1400 DPI | 0.24 | 13.4 cm |
| **100% @ 800 DPI（MC 默认）** | **0.50** | **7.6 cm** |

这组样本落在 4–13 cm，中位约 7.2 cm。MC 的视野是 96° 水平、目标体积大、需要频繁
180° 转身，所以它整体比 FPS 快得多（CS2 选手常见 40 cm+），不能拿 FPS 的舒适区来套。

取**目标 8 cm/360**（略保守于样本中位，照顾串流延迟下不宜过快）。

## 6. 加权求解

各 DPI 下达成 8 cm 需要的 s：

| DPI | 需要的 s |
| --- | --- |
| 400 | 0.70 |
| 800 | 0.487 |
| 1200 | 0.383 |
| 1600 | 0.290 |

按 DPI 分布加权（1000 DPI 归入"其他"，取 0.43）：

```
0.52×0.487 + 0.24×0.290 + 0.17×0.700 + 0.07×0.43
= 0.2532 + 0.0696 + 0.1190 + 0.0301
= 0.472
```

目标改 7 cm 得 0.529，目标 9 cm 得 0.423。**合理区间是 0.42–0.53，中心 0.47。**

`0.5` 落在这个区间内，而且它同时是 **Minecraft 的原生默认值**——一个完全不改设置的
新玩家打开游戏看到的就是它。两个独立理由指向同一个数，没有理由为了 6% 的偏差去选
一个既非众数也非默认的奇数值。

## 7. 不同 DPI 的微调对照

默认值按 800 DPI 校准。如果玩家的鼠标不是 800 DPI，用前端滑块（gain）补偿。
gain 对角度是**立方根**关系：

```
s' = (gain^(1/3) × (0.6s + 0.2) − 0.2) / 0.6,   s = 0.5
```

反解出达成 8 cm 所需的 gain：

| 鼠标 DPI | 建议 gain | 等效 slider |
| --- | --- | --- |
| 400 | 190% | 70% |
| 800 | 100%（默认） | 50% |
| 1000 | 86% | 43% |
| 1200 | 77% | 38% |
| 1600 | 42% | 29% |

侧边栏 → 屏幕 → Pointer sensitivity 调整，值存在
`localStorage['selkies-pointer-gain-v2']`。

## 8. 生效方式

`C:\dev\mc\start-mc.ps1`（计划任务 MCGame 的动作）在启动游戏前：

1. `HKCU\Control Panel\Mouse` 关闭指针加速 + `SPI_SETMOUSE(0,0,0)` 立即生效
2. 把 `options.txt` 的 `mouseSensitivity` 写成 0.5

MC 退出时会用自己的内存值重写 options.txt，所以每次启动都重新写 = "启动即默认"。

写入用 `.NET UTF8Encoding($false)` + 行级正则：PowerShell 的
`Set-Content -Encoding UTF8` 会写 BOM，MC 1.12.2 解析首行键名会带上 U+FEFF。

### 验证

`launch-remote.ps1` 在 JVM 启动前、+8 s、+33 s 各记一次快照：

```
15:23:10 sens pre-launch : mouseSensitivity:0.5 bytes=2260 mtime=15:23:09
15:23:18 sens at +8s     : mouseSensitivity:0.5 bytes=2260 mtime=15:23:09
15:23:43 sens at +33s    : mouseSensitivity:0.5 bytes=2260 mtime=15:23:09
```

字节数可当指纹用：`0.5` = 2260 B，`0.2535211` = 2266 B，差 6 字节。

## 9. 局限

- DPI 分布来自**竞技 FPS 选手**，普通玩家/办公鼠标通常更高（1000–1200），
  所以默认值对这类人偏快，需要滑块往下拉。
- 目标 8 cm/360 是基于 MC 玩家样本的**推断**，不是关节测量的直接数据。
- 链路仍有 100 ms 级端到端延迟（采集轮询 20 ms + 编码 11–15 ms + 游戏帧），
  延迟越大越不适合快灵敏度；这也是取"略慢于样本中位"的原因之一。
