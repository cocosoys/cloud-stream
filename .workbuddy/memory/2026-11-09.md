## #118 修 avsync 空转 + 补音频 5 s 观测

### 根因（先量后改，符合"没有这个数就只能猜"）

线上日志每行都有 `av=`，实测 `av=-140687920ms/70963fix`：媒体钟比墙钟慢 39 小时，
每 2 s 补一个 20 ms 静音帧，两天半补了 70963 次。

真因是**取数**而不是算法：`Loopback::drain()` 在有 500 ms 超时、没声音播放时直接
返回空（注释自己写着 "a machine with no playback at all legitimately never
signals"），于是 `emit_frame` 不被调用、`note_audio` 不前进；而 `fix()` 用的是
`now - started_at` —— 墙钟照走、媒体钟不动，差值就是服务运行时长。

补观测后第一次实测：连续几窗 `audio 5.0s: cap=0 ... (no frames: endpoint idle)`。
在被控机交互会话里播 15 s 声音（schtasks /IT + WPF MediaPlayer，因为 ssh 落在
session 0 没有音频设备）后变成 `cap=240 ... => 48.0 fps, 61.9 kbps`。

### 修法

`State` 里 `started_at` 换成 `wall_us`：**墙钟只在两次 `note_audio` 之间累加**，
间隔 > `MAX_FRAME_GAP`(250 ms) 判为停顿 → 重新对齐（`wall_us = audio_us`），
不把缺口算成漂移。`fix()` 在 `now - last_note_at > 250ms` 时返回 `None`；
warm-up 改成按**音频时间**算（`audio_us < 1s`）。`report()` 改成结构体，多一个
`idle_ms`，日志里 `av=+188ms/5fix idle=14398ms`。

实测：播放中 fixes 涨到 5（首批 200 ms 缓冲按 2 s 一步回压），静音后 4.4/9.4/14.4 s
三窗 fixes **一直是 5**，`idle=` 递增 —— 旧版同样时长会再多 7 次。

### 音频 5 s 摘要（§2.12 的日志那条）

`pipeline` 每 5 s 多一行：`audio 5.0s: cap=240 enc=240 bytes=38721 sil=0 =>
48.0 fps, 61.9 kbps`；`cap=0` 时行尾写 `(no frames: endpoint idle or device gone)`。
`sil` 与 `cap=0` 不是一回事：静音混音仍产包，空闲端点一个不产。

## #120 `target_kbps` 口径修正（追加）

- **根因**：`pipeline/mod.rs:1826` 在每次编码成功后写
  `s.target_kbps = encoder.bitrate()`。而 CBR 下 `set_bitrate_kbps()` 走的是
  `set_quality(ratio)`，`bitrate()` 回读的是 libvpx 按 `base × ratio` 算出的
  **配置值**，与 QoS 控制器内部的 `target_kbps` 是两个量。实测：决策 1581 /
  回读 4527，于是面板出现"throttled: true + target 4527"而实际跑 1.5 Mbps。
- **拆成两个字段**：`PipelineStats.target_kbps` = 决策（QoS 步进 / `vb,` 覆盖 /
  fps 缩放预算），`encoder_kbps` = 编码器自报。写入点只有三处，都在"做出决策"
  的地方；每帧那处改成只写 `encoder_kbps`。启动时用
  `qos.base_kbps()` + `encoder.bitrate()` 播种，避免首秒读 0。
- **health 侧**：`snapshot_fields` 从 14 元组改成 `StreamFields` 结构体 —— 第 15 个
  字段再往元组里塞就没法读了，而 §2.12 的音频三字段还要来。`health.stream` 与
  `stream_stats` 都多一个 `encoder_kbps`（新键，旧面板看不到就忽略，不会画错）。
- **测试**：326 → **331**（新增 `stats::` 两条：两值独立、窗口重置不清码率对）。
  部署 pid **5024**，实测 `target_kbps=5000 encoder_kbps=5000 throttled=false`
  （正常态两值本来就该相等，分叉只发生在改档没落下去的时候）。
- **教训**：一个字段同时承载"想做的"和"做成的"，在两者一致时完全看不出来，只在
  它们分叉的那一刻骗人——而那一刻正是唯一需要读它的时候。同类结构参考
  `default_device` 的 `current` / `previous`。

## #122 WebRTC 在新设备上失败：只放行了 TCP 8080

- **现象**：全新设备（.150，DESKTOP-0L2MMH3）上 WS 正常，切 WebRTC 报
  "媒体路径失败"。前端文案只在 `connectionState==='failed'` 且信令 WS 仍
  `connected` 时弹出，所以不是证书/编码/SDP。
- **根因**：ICE 的 host 候选默认绑 `:0`（`ice` 的 `UDPNetwork::Ephemeral(0,0)`
  → `listen_udp_in_port_range(..., ip:0)`），每个会话一个随机 UDP 端口；
  `open-inbound.cmd` 只放行 TCP 8080 + ICMP。.148 从未暴露是因为那台机器
  **防火墙三档全关**（`deploy-new-host.md` §1.2 原文可作证）。
- **证据**（无需 ssh，用关闭端口是否回 RST 判断防火墙开）：
  .150:8080 OPEN、:9999/:22 TIMEOUT（无 RST = 入站被过滤）、ICMP 通。
- **A（脚本）**：`open-inbound.cmd` 加两条规则 + 改成先删后加：
  `cloud-stream webrtc UDP`(UDP 40000-40049) 与 `cloud-stream app`
  (program 规则，按路径覆盖任意端口)。守卫只按名字查四条（netsh 的
  `show rule` **不打印 program 路径**，按路径 grep 是空想，第一版就是这么错的）；
  安装分支先 `delete rule name=all dir=in program=` 再 add，否则 netsh 会为同名
  规则叠加副本（实测三次跑成 4→7→10 条）。find.exe 不接受"像路径"的搜索串
  （`参数格式不正确`），要按路径匹配得用 `findstr /C:`。
- **B（代码）**：`--webrtc-udp-port-min/max`（默认 40000/40049）→
  `Config::webrtc_udp_ports()` → `MediaSession::new(codec, udp_ports)` →
  `SettingEngine::set_udp_network(UDPNetwork::Ephemeral(EphemeralUDP::new(...)))`。
  区间无效（<1024 或反向）返回 None 退回随机端口，启动日志 warn。
  启动日志：`webrtc ICE will bind UDP 40000-40049 ...`。
- **实测**：`cargo test` 333 passed（+2）；release 冒烟：日志行在；用最小 WSS 客户端

  `netstat` 看到 **172.23.176.1:40002 / 192.168.59.146:40018** —— 每个本机地址
  各占一个端口，所以区间要按"会话数 × 地址数"留余量（50 个够 8 会话）。
  注意 `/api/websockets` 是 WS 媒体端点（会回 `MODE websockets`），不是 WebRTC 信令。
- **本机测试残留**：验证脚本时以管理员跑了 `open-inbound.cmd`，它真的在本机建了

## uninstall.cmd 首次实机卡死（[3/5] 还原录音设备）复盘

**现象**：`[warn] task MCStreamSrv is still registered` 后继续，卡在
`-- [3/5] restoring the default recording device --` 不再输出。

**三个独立根因**
1. `Unregister-ScheduledTask` 在实例收尾期被拒（0x8004131F）。`Stop-ScheduledTask`
   只是请求停止，返回时 State 仍是 Running；错误被 `SilentlyContinue` 吞掉 →
   屏幕上只剩一句 warn。日志里"清单有 1 个进程、[2/5] 却 0 个"正好印证任务
   停成功了、注销失败了。

## enable-ssh.ps1 / enable-ssh.cmd（一次性 SSH 引导）

背景：`.150` 只有 8080 通、22 超时；`deploy.ps1` 靠 ssh 才够得着，是鸡生蛋。

- 新文件 `toolchain/enable-ssh.ps1`（38.6 KB，纯 ASCII + CRLF）与 `enable-ssh.cmd`
  包装（`.ps1` 双击是记事本，且新机执行策略 Restricted）。
- 六步：装 `OpenSSH.Server` 能力 → sshd 自启 + 主机密钥 → 公钥写
  `administrators_authorized_keys`（原子 Set-Acl，SYSTEM+Administrators）→ 防火墙
  只放行 `<ClientAddress>` + 127.0.0.1 并**禁用**系统自带 Any 规则 → 改 config +
  自测 → 自测通过才关 `PasswordAuthentication` 并复测。任一步失败还原备份。
- **本机（146，Win11 26200）完整实跑通过并已还原**：装 → 自测过 → 关密码 →
  用真私钥 `id_ed25519_mc` 登录成功（`server001\user`）→ 密码通道确认 255 →
  卸载能力 + 删规则 + 清 `%ProgramData%\ssh` + 恢复系统规则。`cap=NotPresent`、
  `22` 无监听、`sshd` 服务不存在。
- **四个只有实跑才暴露的坑**（详见 `docs/deploy-ssh-access.md` §8）：
  1. `ssh-keygen -N ''` 在 **PS 5.1 生成带密码的密钥**（pwsh 7 才是空的），
     `-N '""'` 则是两个引号字符当密码。带密码时自测表现为"服务端 Accepted key
     后 Unknown error / 客户端 No more auth methods"，两边都不提 passphrase。
     正解：`-N ""` 拼成**整条命令行字符串**给 `Start-Process -ArgumentList`，并用
     私钥 base64 里的 ciphername 断言 `none`。
  2. `icacls /inheritance:r` + 分开 grant 失败会留下**空 DACL**，此后
     `Remove-Item`/`Rename-Item`/`[IO.File]::Delete`/`takeown`/`icacls /reset`/
     `Set-Acl` 全部 Access denied。只能靠 **SYSTEM 计划任务跑 `icacls /reset`**
     救回（本次已实测救回）。所以现改为一次 `Set-Acl` 原子替换整个 DACL。
  3. `$check` 与 `[switch]$Check` **是同一个变量**（变量名不区分大小写），把
     `sshd -T` 的多行输出赋给 switch → "Cannot convert Object[] to SwitchParameter"，
     行号指向那行却完全看不出原因。改名 `$cfgCheck`。
  4. `New-NetFirewallRule -RemoteAddress` 不接受 `::1`（"多播/广播或环回 IPv6"），
     且异常会中止整个第 4 步。只放 `127.0.0.1`。
     附带：`Get-NetFirewallRule -DisplayName X -Direction Inbound` 参数集冲突；
     `sshd -T` 看不到 Match 块的值，要用 `-T -C user=...`。
- `Add-Type` 不可用、`[Diagnostics.Process]::Start` 被拦、`Invoke-Expression` 被拦；
  可行的是 `Start-Process -PassThru -Wait` 与 `[ScriptBlock]::Create()`。
- 本机 `~/.ssh/config` 新增 `mc-150`（HostName 192.168.59.150，User `Admin`，
  待 .150 报告确认账户名）。
- **待用户**：把这两个文件拷到 `.150` 跑一次，把报告贴回；首次"installing"可能
  停 25 分钟（实测从 Windows Update 下载能力包就是这么慢）。
