## 软件图标：一个 `res\app.ico`，四个出口（74124f4）

用户给了 `C:\Users\user\Desktop\favicon.ico`（759 B，只有 16/32/48 三档位深 32bpp），
拷进仓库为 `res\app.ico`，然后接到四个出口：

| 出口 | 怎么接 |
|---|---|
| `stream-server.exe` | 搭已有 VERSIONINFO 那趟车：同一个 `.rc` 里多一行 `1 ICON` |
| `cloud-setup.exe` | 新增 `embed_icon()`，单独一个 `.rc` |
| Inno 安装器 | `SetupIconFile={#AppIcon}`，define 默认 `..\..\res\app.ico` |
| MSI / "应用和功能" | `Icon` 表 + `ARPPRODUCTICON`（不写就取 msiexec.exe 的图标） |

不引入 winres / embed-resource：直接调 MSVC 自带的 `rc.exe`，省一个依赖和一份
"构建时会不会想联网"的不确定性。缺 rc 只 `cargo:warning`，不失败（和
stream-server/build.rs 既有的"构建永不因为版本资源失败"同一条分寸）。

### 三个为 rc 服务的动作（都不是洁癖）

1. 图标先 `fs::copy` 进 OUT_DIR；
2. `.rc` 里只写相对文件名 `1 ICON "stream-server.ico"`；
3. `Command::current_dir(out_dir)` —— rc 解析相对名用的是**进程当前目录**，
   不是 .rc 文件所在目录。

绝对路径方案要转义反斜杠、要加引号，而 rc 按系统 ANSI 代码页读 `.rc`：仓库
哪天落到带中文的路径下，那种写法会在别人机器上报"找不到文件"。

### 窗口图标是另一处

`WNDCLASSW.hIcon` 原来是 `0` → 标题栏/Alt+Tab 是通用图标，而右键属性里明明有。
改成 `LoadIconW(instance, 1 as *const u16)`。**编号 1 是 build.rs 里 `1 ICON`
的硬约定**；改任一边，LoadIconW 静默返回 0，窗口退回通用图标、不报错。

## 卸载：`unins000.exe` 与 `cloud-setup --uninstall` 的分工（只分析，未改代码）

用户问两者差别。结论：**不是同一层的东西**。

* `unins000.exe` = Inno 编译期生成的"安装日志回放器"。它对本产品一无所知，
  只知道 `unins000.dat` 里记的"这次安装写了哪些文件/目录/注册表/快捷方式"。
* `cloud-setup --uninstall` = 系统集成回收器。它不依赖任何安装记录，靠现场探测
  （任务 XML、进程完整路径、netsh 回读、`--print-config`）决定做什么，所以幂等。

Inno 版里是接力：`[UninstallRun]` 先跑 `--uninstall --keep --yes --quiet`，
再由 Inno 删文件、删 ARP/快捷方式、卸自身。

### 四个会咬人的差别

1. **身份不备份**：`--keep` 在 `save_identity` 之前就 return（uninstall.rs 340-353），
   所以从控制面板卸载 = 配置/证书/录音原值全丢；双击控制台卸载会存到
   `%ProgramData%\cloud-stream\uninstall-backup`，重装 `--ops rollback` 自动放回。
   同一个词"卸载"，两条路结果不一样。**MSI 的 `StopAndUninstall` 也走 `--keep`，
   同一个洞。**
2. **控制台卸载 Inno 版会留死链**：ARP 条目与开始菜单由 Inno 记着，控制台不知道；
   目录删完，那条卸载项指着已不存在的 `unins000.exe`。
3. **Inno 的回收强度取决于目标目录里那份 `cloud-setup.exe`**：`Exec` 失败时它只
   记日志、继续删文件 → 任务/规则残留、服务还在跑、文件被占用 → "卸载不完整"。
   MSI 侧把控制台塞进 Binary 表正是为了躲这个（跑包自带的新版）。
4. **依赖外部状态**：删了 `unins000.dat`（或手工挪过目录）基本就卸不掉，Inno 只
   会报找不到卸载记录；我们的任何状态下都能跑，能收拾"装了一半"的机器。

建议（未实施，等拍板）：给 `--uninstall` 加显式 `--backup-identity`，Inno 的
`[UninstallRun]` 与 MSI 的卸载动作带上，升级路径不带（升级带会每次覆盖备份）。

## 改名之后的升级路径：两个洞（提交 64c23fb）

`cloud-setup.exe` → `stream-setting.exe` 的改名把**升级路径**弄断了，两处都在
`toolchain/inno/cloud-stream.iss`：

1. `PrepareToInstall` 拿 `{app}\stream-setting.exe` 判断"已经有安装"。从老名字
   那版升级上来的机器上没有它 → 判成全新安装 → 停机段（`schtasks /End` +
   `taskkill`）整个跳过 → 旧服务还跑着，Inno 复制 `stream-server.exe` 撞上文件
   占用，装到一半失败。判据改成两个名字认一个。
2. Inno 升级**只按新清单覆盖、不比对旧清单**，老名字那个 exe 会永远留在 `{app}`
   里 —— 而它是能双击的旧工具箱（带"拍快照/回滚"），用户会以为升级没生效。
   新增 `[InstallDelete]` 删 `{app}\cloud-setup.exe` 与开始菜单那条
   `cloud-stream 控制台.lnk`（`{group}` = `{autoprograms}\cloud-stream`）。MSI 侧
   对应 `Console` 组件上的 `<RemoveFile Name="cloud-setup.exe" On="install"/>`。

验证：49 单测通过；用**最小 payload**（一个假 README + 一份 debug 版
stream-setting.exe）设上四个 `CS_INNO_*` 让 ISCC 编了一遍，`[Code]` 与
`[InstallDelete]` 都过，`Successful compile`。这招可复用来给 .iss 做语法体检，
不必等完整 payload（2018 个文件）。

## 收尾：两个真 bug，卸载端到端通了（提交 9b6915e）

`.150` 恢复后（**没有重启**，`LastBootUpTime` 还是 17 小时前 —— 挂起后被恢复的）
拿到现场，结论和最初的怀疑相反：**不是我们的步骤打瘫了机器，是环境侧把 guest
冻住了**。事件日志：10:36:29 之后九分钟零事件，10:45:12 自己进睡眠（id 42）、
5 秒后恢复，11:11:27 时间跳 26 分钟。中间 guest 完全没有事件记录，只可能是宿主
层面暂停。

但现场同时暴露了两个**真 bug**，都比那次失联重要：

### 1 `--uninstall-step` 漏在 `CLI_SWITCHES` 外 → 卸载死锁

装好之后的 exe 旁边一定有 `stream-server.exe`，`decide_mode` 判它是**控制台**。
于是卸载器 `Exec(ewWaitUntilTerminated)` 起的
`stream-setting.exe --uninstall-step task` 开了个 `SW_HIDE` 窗口进消息循环，
两边互相等。**症状极具误导性**：`uninstall::run` 根本没被调用 → 结论文件一字节
没写 → Inno 日志停在那步之前 → 看起来像"卸载器自己卡住"。
证据：手动杀掉那个隐藏窗口（pid 1012）之后日志才出现
`卸载步骤 task 退出码 -1`，从 10:36:51 挂到 11:19:05（42 分钟）；`_unins.tmp`(5460)
的子进程命令行就是 `--uninstall-step mic --quiet --dir "C:\Program Files\cloud-stream"`
—— 每一步都会开一个新窗口（task / procs / mic 各一个 pid）。

排查时踩的坑：`Stop-Process -Name '_unins'` **匹配不到** `_unins.tmp`（进程名带
`.tmp`），所以"杀完"的卸载器其实还活着，继续往下走了两步。

### 2 控制台自己占着 `{app}` → 目录删不掉

`{app}` 里正在执行的 exe 删不掉（影像段不带 `FILE_SHARE_DELETE`）。从控制面板点
卸载时窗口开着 → Inno `Failed to delete directory (32)` → ARP 清空、任务没了、
规则也清了，只剩一个装 `unins000.exe` 的空目录。`.150` 上占着的是 **09:06 双击开
的旧 `cloud-setup.exe`（无参数）**，挂了两小时；杀掉它目录立刻可改名、可删。
现在 `procs` 步连 `stream-setting.exe` / `cloud-setup.exe` 一起收，**排除自己**
（否则这一步自杀，后面三步没人做）。`(145)` = ERROR_DIR_NOT_EMPTY 是 Inno 的
正常重试，别和 `(32)` 共享冲突混。

### 顺带：六步报告互相截断

六步共用 `last-install.txt` 且每步 `start`（截断），实机只留最后一步 `identity`。
新增 `Report::append`（不截断 + 照写抬头），现在六份依次排在一个文件里。

### 最终验证（cloud-stream-setup.exe md5 5987D5CC… / msi AEC74062…）

全新静默安装 exit 0 → 开着工具箱窗口卸载 → `Uninstallation process succeeded /
Removed all? Yes / Need to restart Windows? No`；目录消失、任务 gone、规则 5→1
（只剩人工那条 `ssh 22`）、ARP 0、8080 关闭、进程 0；五步报告各 `RESULT: OK`，
`procs` 那条写着 `[ok] 关掉了同目录下的控制台窗口`。50 单测通过。

### 环境备忘（都会伪装成代码问题）

* `cargo build` 在 Git Bash 里报 `link: extra operand`（Git 的 coreutils `link`
  顶了 MSVC 的），裸 PowerShell 报 `linker link.exe not found`。**一律走
  `.\toolchain\build.ps1`**。
* 远端 `.ps1` 若带中文注释且无 BOM，PowerShell 5.1 按 GBK 解析会成片报
  `意外的标记`。给 `.150` 的探测脚本一律**纯 ASCII**（`toolchain/enable-ssh.ps1`
  早就这么定了）。
* 卸载器"完成"的判据不是 `unins000.exe` 文件消失（第一阶段半秒内就把自己挪进
  `%TEMP%`），而是**没有 `*unins*` 进程且目标目录不存在**。前一版脚本用前者，
  两次都读到"删到一半"的状态。

## 15:40 删掉最后两个 .cmd：口令进配置、取证进 `--diagnose`（`3e47112`）

用户拍板三件事：口令唯一来源 = TOML、`vcruntime140.dll` 随包带、`--diagnose`
九节全做。三件事是连着的：第三件要成立，第二件必须先成立。

### 关键推理链（值得记住的那一条）

`collect-launch-facts.cmd` 存在的唯一理由是"exe 起不来时谁来收现场"，而 exe
起不来的头号原因是缺 VC++（两个 exe 都动态链接 `VCRUNTIME140.dll`，已实测字符串
确认），所以那个工具**必须**不依赖 VC++ → 只能是脚本。而安装器从来不装运行库，
只在 `--finish` 失败后弹框猜一句"最常见的原因是缺 VC++"。
**破循环的办法是把故障本身消灭**（app-local CRT），不是留着诊断脚本。

### 口令：顺带修掉的优先级颠倒

旧实现 `--run` 读 `auth-token.txt` → push `--auth-token` 到 argv，而 argv 压过
配置文件（`config.rs` 里 TOML 先 apply、argv 后覆盖）。于是"在界面上改了口令、
重启不生效"，日志里看不出来。现在 `read_legacy_token` 由 config 层读、排在配置
**之前**：升级上来的机器继续生效，表单设过就以配置为准。
`Kind::Secret` 用双引号 + 转义（`Text` 禁单引号，口令里 `'` 比 `"` 常见），
空输入是错（关鉴权要用 unset 明说）。表单遍历 `config-get --ops-json` 自动生成，
所以加键 = 加一行 `KEYS` + `ES_PASSWORD`，界面零成本。

### 坑

* **vswhere 在这台构建机上返回 `[]`**（BuildTools-only 没有 installer 记录），
  `Find-CrtDll` 第一次静默落到了 System32。`build.ps1` 早有硬编码兜底
  （`C:/Program Files (x86)\Microsoft Visual Studio\2022\BuildTools`），照抄它。
  另外 redist 树里 `onecore\x64\...` 也匹配 "x64"，必须排除。
* **XML 注释里不能有 `--`**：`candle` 报 CNDL0104，位置就是那条写着
  `stream-server.exe --diagnose` 的注释。写成"diagnose 子命令"。
* **`RemoveFile` 必须带 `Id`**：CNDL0010，缺了直接 exit 10。
* **`--diagnose` 会把自己列进"在跑的进程"**：诊断进程映像名就叫
  `stream-server.exe`，`tasklist /FI "PID ne <self>"` 才正确。
* **控制台输出是 ANSI 代码页**（936），按 UTF-8 硬读是问号；
  `MultiByteToWideChar(CP_ACP)` 回退。落盘必须 CRLF（老记事本遇 LF 显示成一行），
  但不能简单 replace（子进程输出本来就是 CRLF，会变 `\r\r\n`）。

## 工具箱新增「开始 / 停止服务」按钮

需求：窗口上原本只有 刷新 / 更新 / 卸载 / 改配置，缺"停一下服务"这个日常动作。

### 决策

- **停止必须连看门狗一起禁用**。任务是 `IgnoreNew` + `PT1M` 重复触发：
  只 `/End` 的话最多一分钟它就把服务拉回来，按钮等于没用。所以顺序固定为
  `/Change /DISABLE` → `/End` → 按路径收残留 → `--restore-mic` → 等进程消失；
  开始则 `/Change /ENABLE` → `/Run` → 等端口应答。顺序抽成 `stop_plan` /
  `start_plan` 两个纯函数，用单测钉住"先禁用再结束"（写反了不报错，只是服务
  一分钟后自己回来）。
- **不需要管理员**，因为任务本来就是 `InteractiveToken` + `LeastPrivilege`。
  哪天有人改回 `Highest` 或注册到 SYSTEM，这条推论就失效 —— 注释里写死了这个
  前提。
- **停止顺手还录音设备**：服务被杀时没人问它，不还的话"停一下"会让这台机器的
  会议软件没声音。走 `--restore-mic`，探测 `MICRESTORE` 标记后再执行。
- **按钮文字跟状态翻**（在跑=「停止服务」/没跑=「开始服务」），文案单一来源
  `service::power_label`，判断单一来源 `service::running`。
- **便携包（无计划任务）走 Spawn**：直接起 `--run`，日志里明说"这次起来的不会
  自己回来"。
- 命令行形态 `stream-setting.exe --service start|stop`（进 `CLI_SWITCHES`，
  且在 `main` 里于角色判断**之前**分流 —— 和 `--purge` 同一类，否则装好的
  exe 会被判成控制台开窗口）。

### 布局

五个按钮等宽 140、间隔 12（5×140+4×12=748），顺序：刷新 / 开始·停止 / 更新 /
卸载 / 改配置。「开停」排第二格，刻意不挨着「卸载」。

### 验证

- 56 单测（新增 6 条：动词解析、停止顺序、开始顺序、便携包不碰调度器、标签语义）。
- 本机 CLI 烟测：`--service` 缺动词 / 错动词 → exit 2；目录里没有
  `stream-server.exe` → exit 1 + `[fail]` 一句。
- `.150`（`DESKTOP-0L2MMH3`）非破坏性验证：`schtasks /Change /DISABLE` 后
  `stream-setting.exe --program-info` 正确显示"已注册，但被禁用（看门狗不会
  拉起服务）"，`/ENABLE` 后翻回"已注册"。
- **未验证**：真机上把「停止」→「开始」连着按一遍。`.150` 上要跑时那边正开着
  会话（日志 `repeat≈296` 有人在看），停一次会把人踢下线，所以留给人手测。

### 环境坑（本轮新增）

- 控制台代码页是 936，而 Rust 的 `println!` 写 UTF-8 → 中文在 cmd/ssh 里是
  `鏈嶅姟` 这种乱码。这是既有行为（`--program-info` 一直如此），不是本次引入；
  要修得在输出前按 OEM 转码，属于另一件事。
- 远端 ssh 传给 cmd 的引号：`\"...\"` 会被吃掉，`dir /b "C:/x/"` 尾反斜杠会
  把引号转义掉（报"文件名、目录名或卷标语法不正确"）。少用嵌套引号。
