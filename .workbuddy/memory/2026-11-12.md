## 软件图标：一个 `res\app.ico`，四个出口（74124f4）

用户给了 `C:\Users\user\Desktop\favicon.ico`（759 B，只有 16/32/48 三档位深 32bpp），
拷进仓库为 `res\app.ico`，然后接到四个出口：

| 出口 | 怎么接 |
|---|---|
| `stream-server.exe` | 搭已有 VERSIONINFO 那趟车：同一个 `.rc` 里多一行 `1 ICON` |
| `cloud-setup.exe` | 新增 `embed_icon()`，单独一个 `.rc` |
| Inno 安装器 | `SetupIconFile={#AppIcon}`，define 默认 `..\..\res\app.ico` |
| MSI / "应用和功能" | `Icon` 表 + `ARPPRODUCTICON`（不写就取 msiexec.exe 的图标） |

不引入 winres / embed-resource：直接调 MSVC 自带的 `rc.exe`，省一个依赖和一份
"构建时会不会想联网"的不确定性。缺 rc 只 `cargo:warning`，不失败（和
stream-server/build.rs 既有的"构建永不因为版本资源失败"同一条分寸）。

### 三个为 rc 服务的动作（都不是洁癖）

1. 图标先 `fs::copy` 进 OUT_DIR；
2. `.rc` 里只写相对文件名 `1 ICON "stream-server.ico"`；
3. `Command::current_dir(out_dir)` —— rc 解析相对名用的是**进程当前目录**，
   不是 .rc 文件所在目录。

绝对路径方案要转义反斜杠、要加引号，而 rc 按系统 ANSI 代码页读 `.rc`：仓库
哪天落到带中文的路径下，那种写法会在别人机器上报"找不到文件"。

### 窗口图标是另一处

`WNDCLASSW.hIcon` 原来是 `0` → 标题栏/Alt+Tab 是通用图标，而右键属性里明明有。
改成 `LoadIconW(instance, 1 as *const u16)`。**编号 1 是 build.rs 里 `1 ICON`
的硬约定**；改任一边，LoadIconW 静默返回 0，窗口退回通用图标、不报错。

## 卸载：`unins000.exe` 与 `cloud-setup --uninstall` 的分工（只分析，未改代码）

用户问两者差别。结论：**不是同一层的东西**。

* `unins000.exe` = Inno 编译期生成的"安装日志回放器"。它对本产品一无所知，
  只知道 `unins000.dat` 里记的"这次安装写了哪些文件/目录/注册表/快捷方式"。
* `cloud-setup --uninstall` = 系统集成回收器。它不依赖任何安装记录，靠现场探测
  （任务 XML、进程完整路径、netsh 回读、`--print-config`）决定做什么，所以幂等。

Inno 版里是接力：`[UninstallRun]` 先跑 `--uninstall --keep --yes --quiet`，
再由 Inno 删文件、删 ARP/快捷方式、卸自身。

### 四个会咬人的差别

1. **身份不备份**：`--keep` 在 `save_identity` 之前就 return（uninstall.rs 340-353），
   所以从控制面板卸载 = 配置/证书/录音原值全丢；双击控制台卸载会存到
   `%ProgramData%\cloud-stream\uninstall-backup`，重装 `--ops rollback` 自动放回。
   同一个词"卸载"，两条路结果不一样。**MSI 的 `StopAndUninstall` 也走 `--keep`，
   同一个洞。**
2. **控制台卸载 Inno 版会留死链**：ARP 条目与开始菜单由 Inno 记着，控制台不知道；
   目录删完，那条卸载项指着已不存在的 `unins000.exe`。
3. **Inno 的回收强度取决于目标目录里那份 `cloud-setup.exe`**：`Exec` 失败时它只
   记日志、继续删文件 → 任务/规则残留、服务还在跑、文件被占用 → "卸载不完整"。
   MSI 侧把控制台塞进 Binary 表正是为了躲这个（跑包自带的新版）。
4. **依赖外部状态**：删了 `unins000.dat`（或手工挪过目录）基本就卸不掉，Inno 只
   会报找不到卸载记录；我们的任何状态下都能跑，能收拾"装了一半"的机器。

建议（未实施，等拍板）：给 `--uninstall` 加显式 `--backup-identity`，Inno 的
`[UninstallRun]` 与 MSI 的卸载动作带上，升级路径不带（升级带会每次覆盖备份）。

## 改名之后的升级路径：两个洞（提交 64c23fb）

`cloud-setup.exe` → `stream-setting.exe` 的改名把**升级路径**弄断了，两处都在
`toolchain/inno/cloud-stream.iss`：

1. `PrepareToInstall` 拿 `{app}\stream-setting.exe` 判断"已经有安装"。从老名字
   那版升级上来的机器上没有它 → 判成全新安装 → 停机段（`schtasks /End` +
   `taskkill`）整个跳过 → 旧服务还跑着，Inno 复制 `stream-server.exe` 撞上文件
   占用，装到一半失败。判据改成两个名字认一个。
2. Inno 升级**只按新清单覆盖、不比对旧清单**，老名字那个 exe 会永远留在 `{app}`
   里 —— 而它是能双击的旧工具箱（带"拍快照/回滚"），用户会以为升级没生效。
   新增 `[InstallDelete]` 删 `{app}\cloud-setup.exe` 与开始菜单那条
   `cloud-stream 控制台.lnk`（`{group}` = `{autoprograms}\cloud-stream`）。MSI 侧
   对应 `Console` 组件上的 `<RemoveFile Name="cloud-setup.exe" On="install"/>`。

验证：49 单测通过；用**最小 payload**（一个假 README + 一份 debug 版
stream-setting.exe）设上四个 `CS_INNO_*` 让 ISCC 编了一遍，`[Code]` 与
`[InstallDelete]` 都过，`Successful compile`。这招可复用来给 .iss 做语法体检，
不必等完整 payload（2018 个文件）。
