## #99 bundle 哈希表 + ETag/304，构建产物清理（已部署 pid 10468）

**四件事按用户定稿落地**：jsdb 全留；剔两个死文件；清被控机 C:/dev；hash 表给浏览器用。

### 1. 死文件
`public/selkies.svg`（全仓库 0 引用）与 `public/brand/.gitkeep`（0 字节占位）用
`git rm` 删掉。vite 拷 public 到 dist，删源即删产物。线上二者现在 404。

### 2. 清单（`dist/.asset-manifest.json`，3.2 KB）
`selkies-dashboard/write-manifest.js` 在 postbuild 里生成。粒度刻意混合：
- **逐文件 13 条**：`index.html`、3 个 `assets/*`、4 个 `codecs/*`、图标、
  `manifest.json`、`brand/logo.svg` —— 每条 `{size, sha256, cache}`
- **单元 5 条**：`jsdb/<platform>` 各一条 `{files, bytes, sha256, cache}`，
  聚合算法是排序后拼 `<path>\0<sha256>\n` 再 hash。理由：gendb 从同一份上游
  快照一次重写全部 1992 个文件，客户端要么有那份要么没有；逐个登记会把表撑到
  ~250 KB 且不增加判断力

`cache` 字段是清单对服务端的指令：`immutable` 只给构建脚本确认过"路径带内容哈希"
的条目（`assets/`），服务端不按扩展名猜。

### 3. 服务端（`http/manifest.rs` 新增 189 行）
- `manifest::policy(dist, rel) -> Policy { etag, immutable }`
- 先查 `files`；落空则按**最长祖先单元**回退，tag = `"<unit sha256>-<rel>"`
  —— 聚合不变 ⟹ 每个成员不变，路径参与拼接 ⟹ 同组不撞 tag
- 单元匹配只在路径分隔符处生效：`jsdb/windows-extra/x` 不算 `jsdb/windows`
- `static::serve` 在查文件缓存**之前**算 policy，保证命中/未命中描述同一文件
- `server` 的 `Route::Static` 读 `If-None-Match` → 304（无 body、无 Content-Length）
- `etag_matches` 弱比较：容忍 `W/`、逗号列表、`*`、空白；空 header 与空 tag 不命中
- `write_http_with` / `write_not_modified` 加到 `http/mod.rs`，`write_http` 保持原签名
- 新增 `Route::Manifest` + `Endpoint::Manifest`（`"http.manifest"`）+ 归入
  `is_observational`。单独一类而不是并进 `Static`：清单把整棵文件树摊开
- 顺着把 `CACHE_MAX_ENTRIES` 256→4096，并加 32 MB 字节预算（2007 个文件，
  256 条会让 jsdb 一刷就抖）

线上实测（192.168.59.148:8080）：
- `index.html` → `no-cache` + `ETag: "sha256-82eba8…"`，带该 tag 请求回 **304**
- `assets/index-vIq8uH4C.js` → `immutable` + ETag（738508 B）
- `jsdb/windows/045e-028e.json` → `no-cache` + `"150b4475…-jsdb/windows/045e-028e.json"`，回 **304**
- `/api/v1/manifest` → 3275 B JSON + `W/"manifest-3275-…"`，回 **304**

## 单被控端 → 多被控端（超卖单台物理机）需求分析

- 背景修正：目标是从 VMware 迁移到**一台真实物理被控机**，用超卖承载多路被控端，避免增加物理设备成本。
- 已确认硬约束：当前被控机 `EditionID=Professional`(Win10 Pro/25H2/26200)，`qwinsta` 仅 services(0)+console(1)，客户端 SKU 无法多会话并存。
- 判断：Windows「虚拟桌面」不是隔离边界；真实边界只有 session / VM / 物理机。同会话多路无法隔离输入/光标/剪贴板。
- 关键代码事实：编码只有 libvpx VP8/VP9（`pipeline/codec.rs` ALL=[Vp8,Vp9]，`encoder.rs:102` 只构造 VPX cfg），**无任何硬件编码（NVENC/QSV/AMF）**；`webrtc/track.rs` 只绑 video/VP8|VP9。→ 物理机有 GPU 也用不上，超卖上限被 CPU 核数锁死。
- 迁移物理机后 4 个会立刻出问题的假设：①无显示器时 `Display::all()` 为空直接 bail（`capture.rs:49-51`）→ 需 HDMI dummy 或 IDD；②`--no-hdr` 是 VMware 专用（`main.rs:68-74`），物理 HDR 屏会让 BGRA8 管线出错；③`ChangeDisplaySettingsW` 变真改物理屏；④音频 loopback 在单会话多路下必串音。
- 结论倾向：超卖形态选 **本机 Hyper-V N 台 guest + GPU-P**（隔离内核级、部署链原样复用、每 guest 独立 8080 与独立合成声卡），而不是 RDS 多会话（需自研 IDD + 会话保活，Parsec/DCV 级工程）。天花板顺序：GPU 3D 吞吐 > NVENC 并发 session 数 > CPU > 内存；**显存不可超卖**。
- 待拍板：目标路数、负载类型（3D 游戏/挂机/2D）、是否有 GPU 与型号、Windows 授权方式。
