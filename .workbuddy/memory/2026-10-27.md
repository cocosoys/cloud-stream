## 项目定位梳理（cloud-stream）
- 全量读盘确认：cloud-stream 是「云游戏/远程桌面自研 Rust 串流后端」工程（路线 A：以 RustDesk 49c89bd 为基底，前端沿用 selkies-webclient 信令契约，替换原 Python/GStreamer selkies-gstreamer 后端）。
- workspace：vendor/hbb_common + vendor/base + vendor/scrap + crates/bench-capture + crates/stream-server（crates/shell 为 stage0 冒烟 crate，独立于 workspace）。
- stream-server 源码约 5.8k 行（debug 口径），模块：config / http / signaling / webrtc / pipeline / dispatch / platform。
- 媒体面：DXGI(GDI 兜底) 采集 → libyuv 缩放 → VP8 软编（vpx）→ TrackLocalStaticSample 写轨；webrtc 0.13 走 rustdesk-org fork。
- 信令面：WS(/api/{app}/signaling/) 承载 HELLO/SESSION/HELLO_OK/SDP/ICE；DC control（有序可靠）承载命令与统计；DC pointer（无序零重传）留给阶段 2 输入。
- 已有能力：#51 光标、#54 WinInputSink 真实注入、#55 剪贴板桥、#56 码率、#60 --no-hdr（VMware SVGA 无 HDR）与 --dump-frame 诊断。
- 验证现状：部署 148（192.168.59.148，Win11 4vCPU/8GB），与 MC 1.12.2-Forge 共存复测通过（CPU 45–48%）；dump-triage/ 存 pre/post BMP、enc-0000.ivf、抽帧 PNG 用于画质归因。

## 纯代码审查：运行期问题清单（未改任何代码）
- P0 输入：win_input.rs:345-353 把前端「流像素」直接 SetCursorPos，不映射回 native(1718x926)，1280x720 流右下角点不到；187-191 用 SetCursorPos 而非 SendInput MOUSEEVENTF_ABSOLUTE，raw-input/指针锁游戏无响应；InputSink::reset() 全仓无调用点，断线后 held_keys 残留→卡键。
- P0 画质：PLI 无节流（webrtc/mod.rs:244-276 + pipeline/mod.rs:500-503），logs/local-test.log 单会话 27 次 PLI 每次强关键帧；encoder.rs:44-52 keyframe_interval 被 #61 实验改成 15（0.5s 一 IDR），与 2.5Mbps 预算冲突。
- P1 正确性：pipeline/mod.rs:9-15/584-598/809 repeat 帧重发上一帧 VP8 P 帧 payload（新 RTP 时间戳），解码端把同一残差叠加到已是该帧结果的参考上→运动场景参考链漂移（对应历史 “color smear”）。应回退为缓存 YUV 重编码或直接丢帧。
- P1 传输：mpsc::unbounded（pipeline/mod.rs:309/316-327）无背压；REMB/TWCC 只注册不消费（grep remb 仅 track.rs 注释），码率无自适应；bitrate_for 按 fps 线性放大（60fps→5000kbps）。
- P2 生命周期：stats task（websession.rs:361-397）永不退出，持有 Arc<MediaSession> 使 PC 与 state_tx 不释放→每次刷新页面泄漏 1 Sampler+1 PC+2 任务；spawn_blocking 的 JoinHandle 被丢弃（:330-335），worker panic 后画面静默冻结；GDI 下每 30s 无条件 Rebuild 一次（:551-567）。
- P3：http 每请求 Connection: close + fs::read 全量；static.rs:68-91 用字符串前缀判越界（**复核为误判**：`Path::starts_with` 是分量比较，`...-evil` 不会通过，无穿越漏洞，故未改）；stats snapshot/reset 双锁竞态；video_on 默认 true（:167）页面打开即烧 CPU。
- 已排除的伪问题：on_message 是 store 替换而非追加（fork data_channel/mod.rs:262），重复 arm 不会重复注入；HDR 帧已在 scrap hdr.rs 转 BGR8，不会出现 8 字节/px 长度不符。

## 代码修复（#62，全部落盘并 release 打包通过）
- 输入面 win_input.rs：新增 `frame_to_screen` / `frame_to_screen_delta`，用随会话共享的 `StreamSettings`（pipeline 会 seed_native 成真实桌面尺寸）把前端「帧像素」映射到物理屏；`m` 走绝对映射、`m2` 走同比例相对缩放；`WinInputSink::new(settings)` 替换 default；`reset()` 增加 `sync_buttons(0)` 释放残留按键/鼠标键。
- 输入注入：`mouse_move_abs` 由 `SetCursorPos` 改为 `SendInput(MOUSEEVENTF_MOVE|MOUSEEVENTF_ABSOLUTE)`（65535 归一化，`absolute_norm`），raw-input/指针锁程序才收得到；移除 Foundation::FALSE / SetCursorPos 依赖。
- 媒体面 pipeline/mod.rs：`repeat` 路径由「重发上一帧 payload」改为「重编码上一帧 YUV」（`last_yuv` 双缓冲 mem::swap，零拷贝），并以 `REPEAT_ENCODE_MAX=8` 限制连续补帧，超额则不发（丢帧不可见，错帧才是花屏）；`keyframe_interval` 15→60；PLI 用 `KEYFRAME_MIN_INTERVAL=500ms` 去抖，并在强制关键帧时补满 repeat 预算（静止画面下 PLI 也能被响应）。
- 传输：`mpsc::unbounded_channel` → `mpsc::channel(SAMPLE_QUEUE=8)`，生产端 `try_send`，Full 时丢该帧余块 + `request_keyframe()`。
- 生命周期：`InnerOutcome::Rebuild{from_gdi}` + `gdi_retries/GDI_RETRY_MAX=3` 关闭 GDI↔DXGI 30s 抖动；帧几何校验（`pb.width/height` + `data().len()`）代替会 panic 的 `copy_from_slice`，异常即 Rebuild；`spawn_blocking` 外套 `catch_unwind`，worker 异常/panic 通过 `PipelineHandle::set_exit_sink/signal_exit` 上报并结束会话（不再静默冻结）。
- 会话 websession.rs：`SessionTasks` 句柄表，清理时 `abort()` 全部 stats/watcher/ICE/event 任务；清理前 `input.reset()`；重复 SESSION 直接忽略；二次 Connected 补发 stream_info/server_settings/connection；stats 快照与 reset_window 合到同一把锁。
- 静态站 static.rs：`Arc<Vec<u8>>` + mtime/len 校验的进程内缓存（上限 256 项），首屏不再每请求读盘。
- 构建：`toolchain/build-ws.cmd` 会因沙箱拦 `reg.exe` 导致 vcvars 静默失败（LNK1181 user32.lib）；改为手工 export MSVC/SDK 的 LIB+INCLUDE、VCPKG_ROOT/VCPKG_MAX_CONCURRENCY/LIBCLANG_PATH 后 `cargo build -p stream-server --release` 成功（2m57s，唯一 warning 是既有的 WinInputSinkRef unused）。注意 PATH 里不能带 /c/dev/tools/pwsh，会被安全策略判定为“从 bash 调 PowerShell”而拒绝。
- 未做（需独立设计，非纯修复）：REMB/TWCC 码率自适应、`video_on` 默认关、Sampler 初始化失败重试。
