## WebSocket + WebCodecs 收尾：四项缺口一次做完

上一轮分析列了四条，全部落地并部署（pid 4908，exe md5 `6C806BAD…`）。
分四笔提交：`c9c20dc`（transport）、`ff2baa0`（stats 租约）、`8e6827c`（WS 三件事）、
`88768f5`（docs），前端另一仓 `6d33406`。

**传输选择的三层优先级，错一层就出"开关没用"**：`?transport=`（一次性，用完
`dropTransportParam` 从地址栏摘掉）> `/api/status.current_mode`（**只在这个浏览器
没存过选择时**播种 localStorage）> localStorage。绝不能再用
`window.__SELKIES_STREAMING_MODE__` 注入 —— core 的 `determineStreamingMode` 把注入
排在存储之前，往 window 上发布会把面板的每次切换在下次加载按回去。

**`/api/status` 从纯文本 `ok` 改 JSON**：`{"status","current_mode","enable_dual_mode",
"transports"}`。看门狗/部署脚本只看状态码，不受影响。`server_settings` 同时补
`enable_dual_mode: {value:true, locked:false}` —— `Sidebar.jsx:2804` 靠它决定渲染不渲染
那个切换项，之前不发是因为没有第二条传输可切。

**`AUTH_SUCCESS,{…}` 那个前缀比想象中重要**：页面是 `startsWith('AUTH_SUCCESS,')` 后
`substring(13)` 再 parse（`selkies-ws-core.js:8407`）。裸 JSON 会落进 `startsWith('{')`
分支，`obj.type` undefined，整条静默丢弃，`clientRole` 永远 null —— viewer 拒不掉，
控制权也不落定。

**扁平封套 vs 嵌套封套**：WS 页面读 `obj.info` / `obj.stats`，不是 `{type,data}`。
这是 `settings_frame` 已经踩过的同一个坑。设置表仍用 `full.get("data")` 拆包复用
`dispatch/output.rs`，不复制第二份 150 行 —— 单一事实来源留在那边。

**JPEG 条纹（`0x03`）是"任何浏览器都能看"的唯一保证**。`pipeline::raw` 全局 tap：
`publish()` 先原子读订阅数，0 就返回；有人订才 `Bytes::copy_from_slice` 拷一份 BGRA；
队列 2 帧、满了丢新帧不阻塞采集线程；`RawSubscription::drop` 自动退订。
线上格式头 6 字节 `[0x03, _, id_hi, id_lo, y_hi, y_lo]`，同帧多条共用一个 id，
`y` 是条带顶端行号，页面画到后缓冲，最后一条到画面底边才呈现。
**只在页面把 encoder 切成 `jpeg` 时才走** —— 前端 `canProcessJpeg` 只认
`currentEncoderMode === 'jpeg'`，而它唯一来源是 `server_settings.encoder`，
所以切 JPEG 必须回 `encoder: {value:"jpeg", allowed:["jpeg"]}`。

**静态桌面是这条路真正的坑**：DXGI 静止时不出帧，`raw::publish` 原来只在新帧路径调用，
探针连上去 4 条（一帧）之后就超时。光标重绘和 `WouldBlock` 重复帧两个分支也得发，
JPEG 观众在黑屏上等的正是这两条。修完：`RESULT ok stripes=8 frames=2 bands=4
y=0/270/540/810`（1080÷4=270）。副产物是发现静态桌面约 4 秒才重复一帧，
所以重复编码 JPEG 的开销可以忽略，不必做"内容未变就跳过"的优化。

**统计窗口不能是单向开关**：`claim_stats` 原来是 `AtomicBool::swap(true)`，第一个订阅者
永久拥有，它一关就没人再 `publish_snapshot`，后来的会话读到定格快照，`encoded_fps`
永远不变 —— 稳定得像正常，错得最难发现。改成 `Mutex<Option<Instant>>` + 3 秒租约，
发布即续租；tick 是 1 秒，连丢 3 拍才判死。

## WS 麦克风上行（#110）：打通 + 两个实测缺陷

- 前端事实（`selkies-core` mic worker）：WS 上行帧 = `[0x02] + Opus`，编码参数写死
  **24 kHz 单声道 / 20 ms / 480 采样**（WASM 回落同一组）。页面收到
  `MICROPHONE_DISABLED` 会 `microphoneEnabled=!1` 并停采集，所以拒绝语义不变。
- 实现：`audio.rs` 把原 `run_uplink` 拆成 `pump(stop, rx, idle)`，WebRTC（idle=None，
  设备常开）与 WS（idle=Some(1.5s)，首包才开、空闲关）共用解码+写设备；
  `MicUplink::start()/push()` 是 WS 注入点，队列 8 包、超长/空包本地丢弃并计数。
  `ws_media.rs` 的 `0x02` 分支接上，同一套 `input_policy` 门禁（拒绝计 `denied_inputs`）。
  health `stream.audio.uplink.live{open,packets,frames,dropped,decode_errors,concealed,
  silence,last_packet_age_ms}`。
- **关键假设已由测试固定**：24k 单声道包用 48k 立体声解码器解 → 960 采样/声道、
  单声道复制到双声道（`a_24k_mono_packet_decodes_into_one_48k_stereo_frame`）。
  不需要服务端重采样器。
- **实测缺陷 1**：注入端旧实现"把 free 全填满"，缓冲里恒为 `数据20ms+静音80ms`，
  4.8s 语音被补 58560 采样/声道（≈1.2s）静音 → 断续"哒哒"声。
- **实测缺陷 2**：只把目标降到 50ms 还不够 —— 每 5ms 转一圈、包每 20ms 来一个，
  若仍"补到位"，静音始终领在数据前，静音反涨到 123840。正确做法：播放中只写手上
  真有的帧，没数据就什么都不写；静音只用于未开播时的端点保活。复测：240 数据帧、
  静音恒 4 帧（80ms，仅开播前），不随时长增长。
- 顺带量到：`Initialize` 请求 100ms，`GetBufferSize()` 实测 4800 帧 = 100ms（真的）。
- 验证（.148，VMware，`--mic-device default` 因为没装线缆）：自建 WS 客户端用 ffmpeg
  产 24k 单声道 Opus（RTP 抓包后剥 12 字节头）发 240 帧 → `packets=frames=240`、
  `decode_errors=0`、`dropped=0`、`open=true`，日志 `microphone uplink open (110 B 首帧)`
  + `uplink playing (140 ms buffered)` + `render open ... buffer=100 ms (4800 frames)`。
  空闲 1.5s 后 `open:false` + `render closed`。
- 部署：md5 `DD3FFE030E1DA853280350833A7E3CC0`，pid 7204。
  **`toolchain/start-stream.cmd` 临时加了 `--mic-device default`**（对讲模式，会自听），
  目的是在这台没线缆的机器上验链路；装了 Steam/VB-CABLE 的机器应改回 `auto`。
- 测试 266 passed。

## #110 租户隔离六项改造（同日晚）

前置分析结论：仓库里原本没有任何 `tenant`/`org`/`account` 概念，只有**会话隔离**，
且默认 `--input-policy shared` → `viewer_may_run` 白名单**从不执行**，观众与主控者
没有区别。

六项逐个落地：

1. **codec/audio 从进程级下沉到 `SharedPipeline`**：删 `codec::CURRENT`、
   `audio::TARGET_BPS`/`ENABLED` 三处 `static`；`StreamSettings` 新增
   `codec/audio_bps/audio_enabled` 三个 `Arc<Atomic*>`（`clone()` 即共享，天然挂
   program）。`audio::spawn(fanout, stop, bps, enabled)`。codec 变更改为
   `kick_display`（只踢同一块屏），SDP 回退只改本会话不再踢所有人。
2. **默认 `InputPolicy::Exclusive`**，SETTINGS/切屏/输入统一过
   `ControlGate::owns()`；WS 侧新增 `touches_program_settings(payload)` 做**字段级**
   裁决（整条拒 `SETTINGS` 会连带丢掉 tabId 与选屏）。
3. **`ws_media` 接入 `security::allow`**：此前这条路径一条裁决都没有，装真策略也
   是空心的。顺序 = 角色（`owns_input` + `viewer_may_run`）→ 策略。
4. **凭据带身份**：`Grant{tenant, role}`、`GrantSpec` 解析 `--auth-grant
   <tenant>:<role>:<token>`（`splitn(3,':')`，令牌放最后因可能含冒号）、
   `Principal.tenant/role`、`TokenGate` 改多条目。`websession::run` 现在收 `grant`
   并把真身份带进 DataChannel 闭包（原来硬写 `Principal::default()`）。
5. **`/api/v1/health` 按租户过滤** + `viewer{tenant,role,credential,hidden_clients}`；
   `encode_node` 走 `StreamInfo::expose_node`，降权时**删键**而不是发空串。
6. **上传目录按租户分根** `<upload-dir>/<tenant>/`（默认租户也走子目录，不留
   直接用根的例外，否则一次列表就把别人的目录名全列出来）+ `--upload-quota-mb`
   （默认 512，0=不限）超额回 507。

**踩到的两个真洞（都已修 + 测试固定）**：
- `Principal::with_grant` 曾把 "viewer + 原本没凭据" 记成 `Credential::None`，而
  `None` 的含义是"这部署没有门" → **任一 viewer 令牌因此拿到操作权**。
- 反过来：`role == Viewer` 且真的没配令牌时，`may_operate()` 为假，会把**单用户
  部署自己的键鼠挡掉**，且日志全绿。修法是判据上移到 `Principal::may_operate()`
  = `role.may_operate() || credential == None`。

`--policy auto`（新默认）：无令牌表 → `allow-all`，有令牌表 → `role-based`。
`role-based` 是唯一真读身份的内置策略。

**复验结果（ws-probe.py）**：
- VP8：`RESULT ok frames=8 keyframes=1 audio=0 text=7 1920x1080 mic=disabled`，
  keyframe 起始、id 连续。
- JPEG：`RESULT ok stripes=6 frames=2 bands=4 jpeg=1 mic=disabled`，
  4 带 y=0/270/540/810 递增，每条 SOI/EOI 齐全。
- 探针 `mic=disabled` 是**预期**：同一时刻浏览器会话握着输入租约（exclusive），
  探针是观众。日志 `identified as tenant=default grant=viewer operates=yes cred=none`
  + `microphone refused (grant=viewer, operates=yes, lease=no)` 把原因写清楚了。
  正向分支（`MICROPHONE_READY`）已由借租约那轮（mic-push.py + session/take）
  连到 `VERDICT=SIGNAL`。

**本轮补的两处**：
- 麦克风拒绝不再静默丢弃：`!may` 时也回一次 `MICROPHONE_DISABLED`（以前只计数），
  否则页面电平条照跳、对面没声音，客户端无从得知。
- `server_settings.microphone_enabled` 从写死 `{false, locked:true}` 改成跟随
  `virtual_mic` 决议（`.148` 上 → `{"locked":false,"value":false}`）。写死会把一条
  已能用的上行藏起来，和 #106 的「广告了没货」是同一个错的另一面。
- WS 身份日志拆两栏 `grant=/operates=`（令牌角色 vs 实际能不能动手）。
