## enable-ssh.ps1 在 .150 第 5 步崩掉：`2>&1` + `$ErrorActionPreference='Stop'`


### 现象

用户把 `enable-ssh.cmd` 拷到 .150（DESKTOP-0L2MMH3，账户 Admin）双击，前四步全绿
（能力包装上、sshd 自启、公钥写入 + ACL 正确、防火墙只放 .146），第 5 步自测时抛：

```
ssh.exe : Warning: Permanently added '127.0.0.1' (ED25519) to the list of known hosts.
所在位置 C:\Users\Admin\Desktop\enable-ssh.ps1:701 字符: 16
+ ... $out = & $sshCli -o BatchMode=yes -o StrictHostKeyChecking=no `
    + CategoryInfo : NotSpecified: (Warning: Perman...):String
```

### 根因

`$ErrorActionPreference = 'Stop'`（第 71 行）+ `& $sshCli ... 2>&1`（第 701 行）。
在 Windows PowerShell 5.1 里 `2>&1` 会把原生命令 stderr 的**每一行**变成
`NativeCommandError` 错误记录，`Stop` 让第一行就终止脚本。触发它的是 ssh **连成功
之后**才打的 `Permanently added`（`UserKnownHostsFile=NUL` 保证每次都打）。

### 后果（远程实测状态，不是猜的）

```
pubkeyauthentication yes
passwordauthentication yes          <- 第 6 步没跑
administrators_authorized_keys: 2 行（1 真 key + 1 行 cs-sshprobe）
%TEMP%\cs-sshprobe-fa7153af\id_probe       <- 一次性私钥还在盘上
```

第 4 步的自建防火墙规则仍在（只放 .146 + 回环），所以暴露面限于构建机。

### 修法（toolchain/enable-ssh.ps1）

1. 新增 `Invoke-Native $exe $args[]`：`Start-Process -RedirectStandardOutput/-Error`
   落临时文件再读，不走管道 → 没有 ErrorRecord，5.1/7 行为一致，返回
   `ExitCode/Out/Err/Combined`，永不抛。
2. 自测加 `-o LogLevel=ERROR`，从源头消掉 `Permanently added`。两处 ssh 调用都换。
3. `sshd -T` 的三处调用也改成 `Invoke-Native`（`$effective`、`$cfgCheck`），
   失败时能打印诊断而不是抛。
4. 新增 `Remove-ProbeKeyLines` / `Remove-StaleProbeDirs` / `Clear-ProbeArtifacts`：
   自测前先清上次残留 → **重跑即修复**，幂等；`Clear-ProbeArtifacts` 在结尾、
   两个 `exit 1` 回滚分支、以及脚本级 `trap` 里都调（`-Check` 下跳过，守住只读契约）。
5. 探针行计数只数 `cs-sshprobe` 行，不再把被顺带删掉的空行算进
   "removed N leftover key line(s)"。

### 验证（Windows PowerShell 5.1.26100，对真机 .150，非模拟）

| 用例 | 结果 |
|---|---|
| 旧写法 `& ssh ... -o UserKnownHostsFile=NUL ... 2>&1` | **THREW RemoteException: Warning: Permanently added '192.168.59.150'...** —— 与用户报告逐字一致 |
| `Invoke-Native` 同参数 | 不抛，exit=0，输出命中，stderr 1 行被捕获 |
| `Invoke-Native` + `LogLevel=ERROR` | 不抛，exit=0，stderr 0 行 |
| `Invoke-Native` 调不存在的 exe | 不抛，exit=-1，错误文本进 Combined |
| `Remove-ProbeKeyLines`（3 行假文件） | 返回 1，剩 1 行真 key，无 BOM，CRLF 结尾，二次调用返回 0 |
| `Clear-ProbeArtifacts` | 临时私钥 + 目录都删掉，key 文件不变 |

脚本本身：`Parser::ParseFile` 干净、996 行、纯 CRLF、纯 ASCII、无残留 `2>&1`。
另顺手删掉 .150 上 `%TEMP%\cs-sshprobe-fa7153af`（里面是 `id_probe` 私钥本体）——
用 ssh 直连确认过：`ssh mc-150` 的 key 登录现在就能用（exit=0）。

## 第二次跑：脚本修好了，但"key-only"是假的

用户重跑后全绿：`removed 1 leftover self-test key line(s)`、

**但拒绝文案里有线索**：`Permission denied (publickey,keyboard-interactive)`。
`kbdinteractiveauthentication` 仍是 `yes`。

### 缺口：KbdInteractiveAuthentication 没关

Windows 的 keyboard-interactive 底层就是账户密码。只关 `PasswordAuthentication`
时，输密码那条路还在 —— 报告却写着 "key-only"。多个来源（CME-804、
Windows OpenSSH 加固实践）一致：两个开关都要关。

修法：第 6 步同时写 `PasswordAuthentication no` + `KbdInteractiveAuthentication no`，
并回读 `sshd -T` 断言两者**都是 no**，否则回滚备份并报 `not key-only; config restored`。
报告段也加了这个字段（原来只打 pubkey/password 两行）。

### 更深的坑：`Set-SshdOption` 追加到 EOF = 写进 `Match` 块

Windows 的 sshd_config 末尾是：

```
Match Group administrators
       AuthorizedKeysFile __PROGRAMDATA__/ssh/administrators_authorized_keys
```

`Set-SshdOption` 原来的兜底是 `$lines += "$name $value"`。实测（.150 只读预演：
复制配置→改→真 sshd `-T` 解析，不碰线上）：

| 追加位置 | 行号 | `sshd -T` 结果 |
|---|---|---|
| EOF | 89（`Match` 块内） | **yes**，改了等于没改 |
| 首个 `Match` 之前 | 87 | **no** |

**新实现**：全局段找到就原地替换；找不到就插在第一条 `Match` 之前；其余重复项
（含被塞进 `Match` 块里的）注释掉 —— sshd 多数指令"先到先得"。

闭环验证：下载 .150 真实 config（88 行）→ 本地 PS 5.1 跑真实 `Set-SshdOption`
→ 上传 → .150 真 sshd `sshd -T -f`：

```
全局:          pubkeyauthentication yes / passwordauthentication no / kbdinteractiveauthentication no
对 Admin 账户: passwordauthentication no / kbdinteractiveauthentication no
              authorizedkeysfile __PROGRAMDATA__/ssh/administrators_authorized_keys
```

### #118 指针整体错开：两套坐标系 + 幽灵指针乘反

用户报"指针严重偏移，两种模式都偏，整体错开固定一段，反复出现过"。根因两条，都在
`addons/selkies-web-core/lib/input.js`：

1. `_sinkBox()` 用四个布尔量（`manual_resolution` / `manualResolution` /
   `isSharedMode` / `streamResolutionDiverged` / `measureCursor`）决定要不要相信
   画面实体；任一路径漏置位就静默回落到 `_windowMath()`（overlay 尺寸 × dpr）。
   那个等式只在 overlay == 流像素/dpr 时成立，于是落点按比例短一截，看着像固定偏移。
   修法：**取消门禁**，有缓冲区有矩形就量它（可见 `<video>` 优先于不可见 canvas，
   否则 canvas 优先，保留 mirror 借矩形的老行为）。
2. `_ghostMove()` 把**服务端像素**增量乘了 `_pointerScale()`（服务端像素/CSS像素），
   应除以它；乘上去是 `scale²` 速度，1:1 时看不出，一缩放就冲出去。历史上
   `068cb92` 与 `351a92c Revert` 是同一处坐标系的两次相反修法 —— 线上增量保持
   1:1 不缩放（#74 游戏灵敏度），幽灵按屏幕表现累加（除以 scale），两者不冲突。

新增 `_reportMappingSkew()`：抽样比对两套映射，误差 >2 CSS px 时 `console.warn`
一次性打印 sink/window/overlay/dpr 全量数字 —— 复发时不用再猜。

文档 `docs/input-coordinates.md`：三层坐标系、本次根因、**6 条禁区**（不许给
`_sinkBox` 加回模式判断、不许拿 `offsetWidth` 当流尺寸、`_windowMath` 只做兜底、
`_relativeToServer` 必须直通、`_ghostMove` 不许改回乘法、新增渲染面必须进 mirror 列表
并调 `syncSinkToCanvasStyle`）、三步排查顺序、五项验证。

## P0 第一步：配置层 + 版本层（#124，代码完成，实机待验）

用户定下"闭环 = 一个可视化 exe 完成安装/卸载/更新/修改"，这是其中"修改"与
"更新"两块的地基。**先做地基不先做 GUI**，因为 GUI 只是壳，配置无落点、版本
无可比，壳做出来也只能是启动按钮。

### 配置层（`src/configfile.rs`，新增 660 行）

优先级 **默认值 < 配置文件 < 命令行**。理由写进代码：配置文件是机器的常态，
命令行是这一次的临时覆盖；反过来会让调试参数在下次看门狗重启后变成常态。

- `--config <path>` 显式指定 → 找不到 = 硬错误（退出码 2）
- 不给 `--config` → 探测 `<exe 目录>/config.toml`，不存在就跳过（**老部署行为
  一个字节不变**，这是整件事能安全引入的前提）
- `FileConfig` 全字段 `Option<T>` + `deny_unknown_fields`：未知键/类型错都是
  **错误而非警告**（静默失效 = "我改了没生效"，比启动失败贵一个量级）。
  枚举值不认识的仍走"保留默认 + warning"，与 CLI 完全一致，不搞第二套校验。
- 空串 = 显式清空（`log = ""` 关掉默认日志），删行 = 用默认值。两种必须区分。
- `--print-config [toml|json]`：打**生效值**，来源走 stderr（stdout 保持纯配置）。
  **逐字节回环**：实测 98 行 TOML → 存回 → 再打印 → `diff` 无差异。
- 新增 `Config::config_source: Option<PathBuf>`：给启动日志用，**刻意不进
  `--print-config` 输出**（否则回环会因来源行不同而破）。
- 顺手修一个既有 bug：`app.rs` 里 `--no-hdr` 的 `log::info!` 写在 `init_logger`
  之前，那行从来没有进过任何日志文件。已挪到 logger 之后。

### 版本层（`build.rs` + `src/version.rs`，新增 300 行）

`version` 0.1.0 → **0.2.0**（此前从项目第一天没动过，所有构建无法区分）。

- `build.rs` 烧 `CS_GIT_COMMIT` / `CS_GIT_DIRTY` / `CS_BUILT_AT`，**任何失败都
  退化成 unknown，绝不 fail build**。`dirty` 是三态（true/false/**unknown**），
  CI 无 `.git` 时不许折成 false。
- Windows VERSIONINFO 由 build.rs 生成 .rc 再调 `rc.exe` 编译；找不到 rc.exe
  只 warn 不中断。实测 exe 属性页：`FileVersion=0.2.0 (c987c75)`、
  `ProductVersion=0.2.0`、`ProductName=cloud-stream`、`Comments=built <unix>`。
- `GET /api/v1/version` → `{version, commit, dirty, built_at, built_at_unix, exe}`，
  **`Cache-Control: no-store`**（更新器问的是"此刻这一份"，缓存住会让它永远
  说"已是最新"）。路由映射到 `Endpoint::Health`，不新开策略面。
- 手写 `civil_from_days` 做 UTC 格式化，不引 chrono。

### 启动脚本分层（`toolchain/start-stream.cmd`）

切分原则：**路径跟部署位置走，参数跟机器走**。

- 进 `stream-config.toml`：host/port/width/height/fps/bitrate/app/mode/
  video_codec/encoder/tune/input_policy/max_sessions/ghost_cursor_idle/mic_*/
  upload_quota_mb/webrtc_udp_*/policy/auth_grants/no_hdr/repeat_every/keyframe_secs
- 留脚本（CLI 覆盖）：`--config` `--dist` `--log` `--tls-cert/--tls-key`（条件）
  `--upload-dir`（探测）`--auth-token`（读文件）。理由：配置文件表达不了
  "这个文件要是有才传"。
- ARGS 从 4 行拼接降到 2 行 + 3 个条件块。
- 新增"缺 stream-config.toml 就拒绝启动并写 watchdog.log"，否则会静默用
  1080p30 默认值起服务（正是这次要消灭的失败形态）。
- 文件名用 `stream-config.toml` 而不是 `config.toml`：`toolchain/config.toml`
  已经是 cargo 镜像配置，同名迟早改错。
- `start-stream.60fps.cmd` 同步改；`install.cmd` 的 `:need` 加这一项；
  `deploy.ps1` 的 `$LauncherNames` 加它（跟着部署覆盖，与"命令行原本写在 cmd
  里"完全同构，行为不变）。

### 部署前必须注意

`stream-config.toml` 的模板是 fps=60。`.150` 是 VMware 4 vCPU，之前手工降到
**fps 15**。部署后要把它改成 15，否则 CPU 会打满。这是"每台机器的差异"，
本轮不解决（属于安装器/更新器：升级时要保留配置）。
