## 输入锁定 kiosk（提交 a8e26c9）

新模块 `crates/stream-server/src/kiosk/`（mod/guard/hook/policy 四文件，约 1600 行）。
三层拦截：注入端 `guard::KeyGuard` → 低级键盘钩子 → 注册表策略；判据只有一份
（keysym 与 VK 都翻译成 `Chord` 再判）。配置 `kiosk` / `kiosk_autolock` /
`kiosk_policy` / `kiosk_hook` / `kiosk_password`；接口
`POST control/kiosk/{lock,unlock,status}`，health 多一个 `kiosk` 段。

三条推翻设计的实测：

1. **钩子必须放行 `LLKHF_INJECTED`**：自家注入的游戏按键在钩子里也是"注入事件"，
   连它们也判会让 `Alt+Tab` 被吃两次，表现是键盘时灵时不灵。
2. **`--unlock` 不能用命名事件**：`Local\` 事件按会话隔离，SSH 进来在 session 0、
   服务在 session 1 → `signaled=false`。改成落 `games\runtime\kiosk-unlock.req`
   文件，服务 400 ms 轮询。
3. **还原记录必须先落盘再改注册表**，否则被 `taskkill /F` 的瞬间原值永久丢失。

联动：`game/start` 成功后才 autolock；`game/stop` 只解 autolock 锁的（手工锁不动，
否则"停止游戏"成了绕过锁定的后门）。

`.128` 实测：lock/unlock 双向、口令错 403、强杀后重启自动还原 2 条策略、
autolock 起游戏 armed=true、停游戏 1.7 s 后自动解锁。473 单测（新增 23）。
`.128` 上现为 `kiosk = true, kiosk_autolock = true`，口令 `cloud-2026`
（哈希存在 `stream-config.toml`）。

顺手修 `toolchain/serve-file.ps1`：原来启动时把 exe 读进内存，一轮部署里"改代码
→构建→再拉"会发上一版，字节数看着完全正常 —— 现象是"新功能没生效"而非报错。
改成每次请求重读。这是本轮"部署了但没生效"的一次真实踩坑（kiosk 字段起初看似
没被解析，实际是拉到了旧二进制）。

### React Compiler 的三个坑（eslint 10 的新规则，都踩了）

1. `react-hooks/set-state-in-effect`：effect 体里直接 `poll()` 被判定为同步 setState。
   改成 `setTimeout(poll, 0)` 起首帧。
2. `react-hooks/preserve-manual-memoization`：`useCallback` 依赖
   `scheduleNotificationRemoval` 被编译器判为"可能被后续修改"→ 直接放弃 memo，
   用普通函数。
3. `react-hooks/purity`：组件体里 `Date.now()` 判为 impure，即使只在点击回调里。
   把构造通知的函数挪到模块顶层。
