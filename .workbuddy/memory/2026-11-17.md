## 输入锁定 kiosk（提交 a8e26c9）

新模块 `crates/stream-server/src/kiosk/`（mod/guard/hook/policy 四文件，约 1600 行）。
三层拦截：注入端 `guard::KeyGuard` → 低级键盘钩子 → 注册表策略；判据只有一份
（keysym 与 VK 都翻译成 `Chord` 再判）。配置 `kiosk` / `kiosk_autolock` /
`kiosk_policy` / `kiosk_hook` / `kiosk_password`；接口
`POST control/kiosk/{lock,unlock,status}`，health 多一个 `kiosk` 段。

三条推翻设计的实测：

1. **钩子必须放行 `LLKHF_INJECTED`**：自家注入的游戏按键在钩子里也是"注入事件"，
   连它们也判会让 `Alt+Tab` 被吃两次，表现是键盘时灵时不灵。
2. **`--unlock` 不能用命名事件**：`Local\` 事件按会话隔离，SSH 进来在 session 0、
   服务在 session 1 → `signaled=false`。改成落 `games\runtime\kiosk-unlock.req`
   文件，服务 400 ms 轮询。
3. **还原记录必须先落盘再改注册表**，否则被 `taskkill /F` 的瞬间原值永久丢失。

联动：`game/start` 成功后才 autolock；`game/stop` 只解 autolock 锁的（手工锁不动，
否则"停止游戏"成了绕过锁定的后门）。

`.128` 实测：lock/unlock 双向、口令错 403、强杀后重启自动还原 2 条策略、
autolock 起游戏 armed=true、停游戏 1.7 s 后自动解锁。473 单测（新增 23）。
`.128` 上现为 `kiosk = true, kiosk_autolock = true`，口令 `cloud-2026`
（哈希存在 `stream-config.toml`）。

顺手修 `toolchain/serve-file.ps1`：原来启动时把 exe 读进内存，一轮部署里"改代码
→构建→再拉"会发上一版，字节数看着完全正常 —— 现象是"新功能没生效"而非报错。
改成每次请求重读。这是本轮"部署了但没生效"的一次真实踩坑（kiosk 字段起初看似
没被解析，实际是拉到了旧二进制）。

### S4 之后：启动参数改造 E+A（commit `4ed46d5`）

用户诉求原话："参考 PCL2，避免由于一个参数的改动导致启动失败。"

- **参考的 PCL2 源码**：`Hex-Dragon/PCL2` → `Modules/Minecraft/ModLaunch.vb`。
  六个机制：模板驱动（`minecraftArguments` / `arguments.game|jvm`）、二十余个
  `${…}` 占位符、`inheritsFrom` 链式向上、`McJsonRuleCheck` 规则过滤、
  **拼接后去重（游戏参数新值覆盖旧值，JVM 与 `--tweakClass` 保留旧值）**、
  natives 只解 `.dll`。
- **根因**：`plan()` 把 1.12.2 的参数手写成 `Vec<String>`，同时实例里也写
  `main_class`/`tweak_class`，而 version json 里本来就有 `mainClass` 和
  `minecraftArguments` 里的 `--tweakClass`。双写 + 硬编码 = 改一个字母就
  `Could not find or load main class`。
- **A**：两个字段变可选覆盖，留空从 json 取。实测删字段后 `# main` 与 `command`
  行逐字不变 —— 这是 A 的验收方式。
- **E**：`LaunchPlan` 拆 jvm/main/game 三段，`ArgToken{text, origin}` 标
  builtin/json/instance；`--print-game` 分段输出 + 整行 command。三条校验：
  `${` 残留、重复 `--flag`、主类/tweaker 在 classpath 里（读 zip 中央目录，
  只读 EOCD+CD，无新依赖）。`java.verify_classes` 可关。
- **顺带发现（真实隐患）**：`.128` 的 `.minecraft\libraries\org\scala-lang` 下
  5 个 jar 只有 **689 字节**（内容是下载失败的错误页，不是 zip）：
  `scala-continuations-library_2.11-1.0.2_mc`、`scala-continuations-plugin_2.11.1-1.0.2_mc`、
  `scala-parser-combinators_2.11-1.0.1`、`scala-swing_2.11-1.0.1`、`scala-xml_2.11-1.0.2`。
  1.12.2 Forge 不加载它们所以一直没暴露。**校验器拒得对**，别急着放宽。
- **踩坑（部署）**：Windows OpenSSH 用 `cmd /c "命令"` 执行，内部再套双引号必坏
  （`copy /y x "C:\Program Files\..."` 报"命令语法不正确"）。可行写法只有三种：
  ① `powershell -NoProfile -Command Copy-Item C:\PROGRA~1\... -Force`（短路径无空格无引号）；
  ② 内容走 base64 → `cmd /c echo <b64>>file` → `certutil -decode`；
  ③ 无引号的纯 cmd。
  另：`findstr /v` 过滤 JSON 行会**丢掉末尾的 `}`**（957 B vs 1112 B 那次），
  补一行 `echo }>>file` 才恢复 —— 以后改 JSON 别用 findstr。
