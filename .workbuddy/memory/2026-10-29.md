### CF_DIB 与 BMP 的区别（做 #18 才踩到）
Windows 应用交换 `CF_DIB` = `BITMAPINFOHEADER` + 倒序像素，**没有**
`BITMAPFILEHEADER`。BMP 文件 = 14 字节文件头 + DIB。浏览器只认 `image/png`，
所以 `clipboard_image.rs` 做三向转换：PNG/BMP/裸 DIB 自动分派解码 → `to_dib()`
写回 → `dib_to_bmp()` 给需要的程序。
坑：`BI_RGB` 的第四字节"未使用"，多数程序写 0，直接当 alpha 会粘出全透明矩形
→ `dib[o+3] == 0` 时按不透明处理。

### #26 音画同步：第一版是错的，真实日志一眼看出来
第一版比较两路**介质时钟**（`video_us - audio_us`），部署后：
```
av=-16199ms/40fix
```
一分钟 40 次校正、偏斜负 16 秒。不是实现错，是**前提错**：本管线视频"变化才发"，
静态桌面 1–2 帧/秒、音频严格 50 帧/秒，`write_sample(data, spf)` 对每帧都盖
`spf` → 视频 RTP 时间戳是**解码器增量**不是时间轴，跟墙钟无关。
中间试过"视频速率门控"（`REFERENCE_MIN_RATE=0.5`）也失败——按媒介时间/墙钟算
速率，静态桌面那点帧数仍会周期性越过门限。
最终整模块重写为「**把音频媒体时钟钉在墙钟上**」，与视频彻底解耦；回归测试

`av=+13ms/0fix`、`+22ms/0fix`、`+15ms/0fix` —— 静止桌面不产生任何校正，正是想要的。

### 症状与误判

### 真因：CSS 模板字符串里写了反引号
`stats-hud.js` 的样式是
```js

  /* ... (`.toggle-handle` / `.toggle-indicator` in ...) ... */

```
注释里那四个反引号里，第一个把模板字符串提前结束，剩下的

### 为什么连左侧工具栏也没了
`dashboard/src/main.jsx:70` 先 `await window.selkiesCoreInitialize()`，
第 80 行才 `ReactDOM.createRoot(...).render()`。`installStatsHud()` 是
`selkiesCoreInitialize` 的最后一步，异常冒出来把 React 挂载整段带走。
所以"工具栏消失"和"胶囊不见"是**同一个 bug 的两种表现**。

### 定位手法（值得复用）
无头 Edge 的 `--screenshot` 在 `load` 时就截，拿不到 React 挂载后的画面，
`--dump-dom` 又是 0 字节。有效组合是：
1. `python -m http.server` 起服务（必须用后台任务，`&` 子 shell 会被回收）；
2. 探针页里 `await import('./assets/selkies-core-*.js')`，把

   直接 `textContent` 画在页面上；
3. `--headless=new` + `--window-size` + `--screenshot`，**不要加
   `--virtual-time-budget`**（会卡到超时，截不出来）；
4. 截图后用 ViewImage 直接读绿色诊断文字 —— 等于在无 CDP 的情况下的 console。
探针在 `load` 前执行（module 是 defer），所以同步代码的输出能被截到；
`setTimeout` 之后的看不到，要观察的状态就用 URL query 预设。

`selkiesCoreInitialize` 里给 `installStatsHud()` 包 try/catch。可选浮层不该有能力

以及：`position: fixed` 看起来"没渲染"时，先确认元素存在，别先调坐标。

## #34 一键部署落地（`73b214f`）

`toolchain/deploy.ps1`（本机）+ `toolchain/deploy-remote.ps1`（被控机，纯 ASCII，
因为 5.1 会把无 BOM 的 .ps1 当 ANSI 读）。说明书 `docs/deploy-one-click.md`。

实测：两次全量 48.7s（pid 3200 / 5956，session 1）、一次回滚（pid 1888）、
Bootstrap 与 DryRun 各一次。roadmap 总账 29/2/3 → 30/2/2。

### 三个不显然的决定
1. **远端动作写成文件再 `-File` 执行**。内联要穿 bash→ssh→cmd→powershell 四层
   引号，`$p=C:\dev\x` 会被吃（本轮真踩了，浪费一个周期）。
2. **换文件前禁用计划任务**。看门狗每分钟触发，不关就在 kill 与 swap 之间把旧
   exe 拉起来占用，文件覆盖失败。
3. **体检三重判据**：`/api/status` 200 + 进程启动时间晚于部署开始 + 日志
   `listening on`。只查 200 会把「新 exe 没起来、旧进程被看门狗拉起」判成功。

### 写脚本时自己踩的坑
- `-SkipBackend:$false` 这种写法穿过 ssh→cmd 会被当「参数名:值」→ 开关只在为真时加。
- `npm.cmd -> node` 会绕过 PowerShell 管道直接写控制台，静默模式靠 `*>` 重定向
  文件才管用（`& npm ... 2>&1` 抓不到）。
- `Test-Path 'a' -and Test-Path 'b'` 是参数绑定错误，要加括号。
- **不要设 `[Console]::OutputEncoding`**：只改解码不改代码页，`> log.txt` 会写出
  UTF-8 套 GBK 的二次编码（"棰勬"）。脚本改成完全不动它。

### ssh 自启
装完 OpenSSH Server 默认是「手动」，重启一次就再也连不上。脚本每次部署幂等修正
（把 sshd 启动类型设为自动 + 22 端口放行），连不上时把这几行原样打出来让人到
控制台敲。

## 游戏模式指针偏慢 11%：相对增量漏了画面缩放

两种模式的差别是**绝对 vs 相对**，不是「游戏」这个开关：

| | 全屏模式 | 游戏模式 |
| --- | --- | --- |
| 指针锁 | 无 | Pointer Lock |
| 消息 | `m,x,y,mask` 绝对 | `m2,dx,dy,mask` 相对 |
| 注入 | 绝对定位，绕过系统鼠标曲线 | `SendInput(MOUSEEVENTF_MOVE)` |
| 客户端缩放 | 走 `_pointerScale()`（CSS→帧像素） | **没走** |
| 本地光标 | 页面自绘，跟手即时 | 锁定时没有，只能看视频里的远端光标 |

`_pointerScale()` = `sinkW / boxW` = 帧像素/CSS 像素。实测本机视口 1714×922
（100% 缩放）、被控机 1920×1080 → 0.893，所以相对模式每 1 CSS px 只走
0.893 CSS px，慢 10.7%，窗口越小差越多；绝对模式因为除过这个系数所以永远精确。

改法只有一行：`_relativeToServer` 乘上 `_pointerScale()`（逐轴），`pointerGain`
仍在其上叠乘。#74 当年删掉这个系数是怕游戏镜头灵敏度随窗口变 —— 对镜头成立，
对桌面指针不成立（指针本来就该跟手）。这处要记住**方向容易搞反**：慢是因为
「显示的图比帧小」，需要乘的是帧/CSS（>1），不是乘比例本身。

延迟那半边**不是 bug**：两模式的视频链路延迟相同（采集 poll 20ms + 编码 +
网络 + 解码 + 显示），全屏模式有本地自绘光标把延迟遮住，锁定模式只能看远端
光标，等于把链路延迟直接摊开。要压只能做本地预测光标，但会和视频里的主机
光标重影，得先确认视频里到底画没画主机光标。

验证靠 Node + DOM 垫片直接驱动 `Input`：10 CSS px → 11/12 远端像素（改前
10/10）、3×1px 带余数累计 3/4（改前 3/3）、1:1 画面不变。前端提交 `068cb92`。

## 指针偏慢的收尾：回退绕过方案，改从源头（#89 dr,WxH）

用户不要"调灵敏度"这条路，要"强制被控端分辨率 = 本机视口"。所以 `068cb92`
被 revert（`351a92c`），改成后端真的去改显示器模式。

**根因的准确说法**：不是灵敏度，是「帧像素 / CSS 像素」这个比值不为 1。`r,WxH`
只改编码目标 —— 1920×1080 的桌面被挤进 1714×922 的帧，绝对路径乘了 1.12 所以
点得准，相对路径不乘所以慢 10.7%。让桌面本身变成 1714×922，比值变 1，两条路
一起正确，且文字不再被重采样。

**Win32 三个必须记住的点**：
1. `ChangeDisplaySettingsW` 必须配 `CDS_TEST` 先用一次。这是「打错数字黑屏」与

2. 视口尺寸（1714×922）永远不在 `EnumDisplaySettingsW` 的列表里，所以真正的

3. `DEVMODEW` 没有 `Default`，且要先用 `ENUM_CURRENT_SETTINGS` 读一份再改

   位深会被一起清零。

**尺寸取哪个**：`Input.getStreamCssSize()`（画面元素渲染尺寸），不是
`getWindowResolution()`（整页 × dpr，含仪表盘边框）。取错了被控端会比视频大

## 15:20 帧率上限 60→240 + 「不限制」档；侧栏滑块统一成 SliderField

**需求原话**：Pointer sensitivity 改中文；帧率解除 60 限制、最右一档是"无限大"、
label 右侧加可填写的输入栏；把这份样式写进样式库，其它圆点滑块全部改成它。

**线上契约**：`framerate: 0` = 不限制。0 不是帧率，任何地方不许拿它做 `1/fps`、
比 min/max、乘码率系数。`spf()` 回 `ZERO`，`sample_spf()` 回 1ms，
`budget_fps()` 回 240（码率预算、IVF 头、关键帧 backstop 都用它）。

**关键取舍**：`spf = 0` 若仍走原 `settle_beat`（滑窗截止 + 自旋），每拍都判定

死循环，吃满一个核。改成 `CaptureWorker::wait_frame(8ms)`：阻塞在采集线程发布帧
的那个 condvar 上，唤醒就是新帧到达本身 → 拍频 = 显示器刷新率，静止时 8ms 一次。
门控关闭那一支要单独 `sleep`：邮箱里还留着关门那帧，`wait_frame` 会立刻返回。

**RTP 时长**：不限模式不能用 0（每帧同一时间戳，浏览器当重复帧），也不能用固定
1ms（媒体时钟慢一千倍）。转发器按上一拍 `sample.beat` 到这一拍的实测间隔填，
clamp 0.5ms..200ms。

覆盖层画质、音频码率、指针灵敏度。滑块名字去掉括号里的当前值 —— 值只出现在
输入框。`framerateStopIndex` 必须留着：显示器刷新率在轨道上可能出现两次

**被 0 噎住的三处**（都在前端）：`parseFloat(...) || DEFAULT_FRAMERATE` 会把
