### CF_DIB 与 BMP 的区别（做 #18 才踩到）
Windows 应用交换 `CF_DIB` = `BITMAPINFOHEADER` + 倒序像素，**没有**
`BITMAPFILEHEADER`。BMP 文件 = 14 字节文件头 + DIB。浏览器只认 `image/png`，
所以 `clipboard_image.rs` 做三向转换：PNG/BMP/裸 DIB 自动分派解码 → `to_dib()`
写回 → `dib_to_bmp()` 给需要的程序。
坑：`BI_RGB` 的第四字节"未使用"，多数程序写 0，直接当 alpha 会粘出全透明矩形
→ `dib[o+3] == 0` 时按不透明处理。

### #26 音画同步：第一版是错的，真实日志一眼看出来
第一版比较两路**介质时钟**（`video_us - audio_us`），部署后：
```
av=-16199ms/40fix
```
一分钟 40 次校正、偏斜负 16 秒。不是实现错，是**前提错**：本管线视频"变化才发"，
静态桌面 1–2 帧/秒、音频严格 50 帧/秒，`write_sample(data, spf)` 对每帧都盖
`spf` → 视频 RTP 时间戳是**解码器增量**不是时间轴，跟墙钟无关。
中间试过"视频速率门控"（`REFERENCE_MIN_RATE=0.5`）也失败——按媒介时间/墙钟算
速率，静态桌面那点帧数仍会周期性越过门限。
最终整模块重写为「**把音频媒体时钟钉在墙钟上**」，与视频彻底解耦；回归测试
`only_the_wall_clock_matters`（没有任何视频帧时也必须零校正）。重部署后实测
`av=+13ms/0fix`、`+22ms/0fix`、`+15ms/0fix` —— 静止桌面不产生任何校正，正是想要的。

## 修 #87 的致命回归：「粉色胶囊不显示」= 整个 dashboard 没挂载

提交：前端 `bbd0c3a`。

### 症状与误判
用户说右侧那条胶囊看不到，猜是"渲染位置错误"。第一反应去量 `position: fixed;
right: 0` 的几何，怀疑被裁。**不是位置问题**——元素根本没被创建。

### 真因：CSS 模板字符串里写了反引号
`stats-hud.js` 的样式是
```js
style.textContent = `
  /* ... (`.toggle-handle` / `.toggle-indicator` in ...) ... */
`;
```
注释里那四个反引号里，第一个把模板字符串提前结束，剩下的
`toggle-handle` 被解析成 `toggle - handle` 两个标识符 → 语法合法（构建照过），
运行时 `installStatsHud()` 第 144 行抛 `ReferenceError: handle is not defined`。
样式还没写进 shadow root，host 也没 append → 面板 + 胶囊一起消失。

### 为什么连左侧工具栏也没了
`dashboard/src/main.jsx:70` 先 `await window.selkiesCoreInitialize()`，
第 80 行才 `ReactDOM.createRoot(...).render()`。`installStatsHud()` 是
`selkiesCoreInitialize` 的最后一步，异常冒出来把 React 挂载整段带走。
所以"工具栏消失"和"胶囊不见"是**同一个 bug 的两种表现**。

### 定位手法（值得复用）
无头 Edge 的 `--screenshot` 在 `load` 时就截，拿不到 React 挂载后的画面，
`--dump-dom` 又是 0 字节。有效组合是：
1. `python -m http.server` 起服务（必须用后台任务，`&` 子 shell 会被回收）；
2. 探针页里 `await import('./assets/selkies-core-*.js')`，把
   `getBoundingClientRect()` / `getComputedStyle(el,'::before')` / `localStorage`
   直接 `textContent` 画在页面上；
3. `--headless=new` + `--window-size` + `--screenshot`，**不要加
   `--virtual-time-budget`**（会卡到超时，截不出来）；
4. 截图后用 ViewImage 直接读绿色诊断文字 —— 等于在无 CDP 的情况下的 console。
探针在 `load` 前执行（module 是 defer），所以同步代码的输出能被截到；
`setTimeout` 之后的看不到，要观察的状态就用 URL query 预设。

数值结果（1200 宽视口）：`dock x=923 w=277`（右边缘对齐 1200）、
`tab x=1185 w=15`、`pill=4px/44px rgb(236,72,153)`、`rows=10`；
`?tucked` 时 `tabx` 不变、`panx=1193`、`opacity=0`。

### 顺带加的结构性防护
`selkiesCoreInitialize` 里给 `installStatsHud()` 包 try/catch。可选浮层不该有能力
拖垮主界面——这次它办到了，而且失败信息完全指不到源头。

### 教训
**模板字符串里的注释不要用反引号**（CSS 常见 `.class` 引用习惯正好踩雷），
这已经是第二次（前一次是 minified chunk 也报同一个 `handle is not defined`，
当时误判成"chunk 不自包含"）。
以及：`position: fixed` 看起来"没渲染"时，先确认元素存在，别先调坐标。

## #34 一键部署落地（`73b214f`）

`toolchain/deploy.ps1`（本机）+ `toolchain/deploy-remote.ps1`（被控机，纯 ASCII，
因为 5.1 会把无 BOM 的 .ps1 当 ANSI 读）。说明书 `docs/deploy-one-click.md`。

实测：两次全量 48.7s（pid 3200 / 5956，session 1）、一次回滚（pid 1888）、
Bootstrap 与 DryRun 各一次。roadmap 总账 29/2/3 → 30/2/2。

### 三个不显然的决定
1. **远端动作写成文件再 `-File` 执行**。内联要穿 bash→ssh→cmd→powershell 四层
   引号，`$p=C:\dev\x` 会被吃（本轮真踩了，浪费一个周期）。
2. **换文件前禁用计划任务**。看门狗每分钟触发，不关就在 kill 与 swap 之间把旧
   exe 拉起来占用，文件覆盖失败。
3. **体检三重判据**：`/api/status` 200 + 进程启动时间晚于部署开始 + 日志
   `listening on`。只查 200 会把「新 exe 没起来、旧进程被看门狗拉起」判成功。

### 写脚本时自己踩的坑
- `-SkipBackend:$false` 这种写法穿过 ssh→cmd 会被当「参数名:值」→ 开关只在为真时加。
- `npm.cmd -> node` 会绕过 PowerShell 管道直接写控制台，静默模式靠 `*>` 重定向
  文件才管用（`& npm ... 2>&1` 抓不到）。
- `Test-Path 'a' -and Test-Path 'b'` 是参数绑定错误，要加括号。
- **不要设 `[Console]::OutputEncoding`**：只改解码不改代码页，`> log.txt` 会写出
  UTF-8 套 GBK 的二次编码（"棰勬"）。脚本改成完全不动它。

### ssh 自启
装完 OpenSSH Server 默认是「手动」，重启一次就再也连不上。脚本每次部署幂等修正
（把 sshd 启动类型设为自动 + 22 端口放行），连不上时把这几行原样打出来让人到
控制台敲。

### 为什么 `-SkipBuild` 会把旧前端发上去（`79aa5ee`）
打包被塞在 `if (-not $SkipBuild)` 里。`-SkipBuild` 本意是"不重新编译"，但打包
不是编译 —— dist 是磁盘上已构建的事实，zip 只是快照。于是 10:58 重新 build
了 dist，部署日志全绿，线上 `index.html` 引用的还是 10:39 的 `index-DGAHc0jc.js`。
判定线上是不是新产物：`curl -sk https://<host>:8080/ | grep -o 'assets/[^"]*'`，
别看日志。

### 第一版把 startup 也拒了
`--policy deny-all` 启动即 `bail`，探针自己先死。改为 `DenyAll` 显式放行
`startup`（它不是外部可达面，是进程自己在装配），并加单测锁住。

### 教训
- **探针策略必须能启动**。覆盖率探针的前提是有一台活着的进程去探。
- **日志提示文本不要复用真实日志前缀**。原来那行 INFO 里写了
  `see \`authz deny surface=\``，导致 `grep -c "authz deny surface="` 永远至少
  得 1，把"零拒绝"验成了"一拒绝"。
- **前端的 `addListener` 这种单点收口价值很大**：60 多处注册，一处改动全覆盖。
  找收口点比逐处改快一个数量级，也不会漏。
- **剪贴板旁边那对 keydown/keyup 只是本地节流**，不显式归 `lifecycle` 就会按
  事件名落进 `input.keyboard`，于是"拒绝键盘"会顺带弄坏粘贴的节流逻辑。
